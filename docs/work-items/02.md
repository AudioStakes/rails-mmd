# 対応02：Rails matrix bundle cacheを再利用可能にする

- 優先順位: 2
- 状態: 完了
- 題名: Rails matrix bundle cacheを再利用可能にする
- 最終更新: 2026-07-19
- 元資料: docs/verification-performance-plan.md

## 元の指示

Make the Rails matrix bundle cache deterministic and reusable for local and CI
verification, keyed by Ruby version and lockfile content.

## 完了条件

- Cache pathがRuby versionとfixture lockfile内容から決定的に導出される。
- 明示cache rootを別worktree/CIから再利用でき、defaultはrepository-localに留まる。
- Lockfile変更時に異なるcache keyとなり、unchanged lockfileでは同じkeyとなる。
- Cold/warm、disk、並行実行リスクを計測し、既存方式より明確な実用上の利点がある。
- 専門レビューのCritical/Important指摘が解消し、fresh matrix/default gateが成功する。

## 既存成果物の確認

- 2026-07-19: 現行RunnerはBUNDLE_PATH=.bundle/rails-matrix/gems/<ruby_version>を固定し、同一worktreeでは189MBのcacheを再利用する。別worktree/CIへのcache root overrideとlockfile内容によるkey/invalidationはない。項目1計測時のmatrixはcold 42.037秒、warm 7.924秒。

## 調査・知見

- 2026-07-19: Architecture review recommended per-lock SHA-256 over combined digest: smaller invalidation scope、selected-pair reuse、same-Ruby concurrent writers分離。Native extensionはabsolute cache pathを埋め込むためstable rootが必要。parallel jobsのsame digest live-writeは残存risk。

## 機械化方針

- 2026-07-19: Ruby標準Digest::SHA256、既存Manifest/Pair/Runner、環境変数によるcache root overrideを候補とする。新規依存・SaaS・秘密情報・GitHub Actions workflowは追加しない。入力はfixture Gemfile.lock、出力は決定的BUNDLE_PATH。lock消失/読取失敗はverificationを停止する。

## Codexが行うこと

- 2026-07-19: 設計レビュー後にprototypeを実装し、別cache rootのcold/warm、path key、lock変更時の分離、disk/cold overheadを計測する。明確に有効な場合のみレビュー修正・コミットする。

## 本人だけが行うこと

- 2026-07-19: なし。外部CI設定変更は行わず、repository-local interfaceとdocsまでCodexが実施する。

## 実行記録

- 2026-07-19: BundleCacheを追加し、default repository-local rootとRAILS_MMD_MATRIX_CACHE_ROOT override、Ruby/series/lock SHA-256 path、empty root/missing lock failureを実装。Unit/integration 16 examples/0 failures、対象RuboCop 2 files/no offenses。空共有root cold 41.908秒、warm 7.208秒、3/3 pass。cache size 259MB（現行shared-per-Ruby 189MB比+70MB/+37%）。
- 2026-07-19: Review fixes: empty lockfileを明示拒否しspec追加。Runner subprocessでcomputed BUNDLE_PATHを記録するend-to-end integration spec追加。Docsをtrusted owner-controlled restore-only/single-writer/job-local writable root契約へ限定。別detached worktreeで同じabsolute cache rootを再利用すると7.690秒、empty root対照41.068秒（33.378秒/81.3%短縮）、双方3/3 pass。
